# Локальный разбор кредитного отчёта

Первая рабочая часть пилота: загрузка PDF ПКБ или краткой формы ГКБ, проверка извлечённых обязательств, редактирование и описательная аналитика. Никаких прогнозов одобрения, рекомендаций по улучшению рейтинга или подключений к банковскому движку.

## Запуск в Windows

Запустите `run.cmd`, затем откройте <http://127.0.0.1:8765>.

Скрипт ищет Python с зависимостями в `.venv`, PATH и установленном Codex runtime. Сам ничего не устанавливает. Для другого порта: `run.cmd -Port 8766`.

Для обычной установки Python 3.11+:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Остановка — Ctrl+C в окне сервера. Сервер слушает только `127.0.0.1`. Это локальная версия для разработки; она не предназначена для публикации в Интернете или общего доступа участников.

## Страницы сайта

- `/` — загрузка отчёта.
- `/overview` — обзор известных сумм и платежей.
- `/loans` — список обязательств и фильтры.
- `/simulator` — сценарий полного закрытия выбранных договоров.
- `/review` — проверка и исправление распознанных значений.
- `/method` — методика, допущения и работа с данными.

Переходы по меню и история браузера сохраняют разбор, доход, выбор в симуляторе и несохранённые поля в памяти. Перезагрузка документа и новая вкладка начинают без отчёта; на страницах расчёта будет приглашение загрузить PDF. Данные не записываются в браузерное хранилище или серверную сессию. Неизвестные адреса возвращают страницу 404. Иконка сайта — предоставленный PNG-логотип.

## Как проверить

1. Нажмите «Открыть пример». Синтетический PDF пройдёт через тот же загрузчик и парсер, что собственный файл.
2. Ожидаемые цифры примера: 3 действующих договора, 1 закрытый; известная задолженность 1 750 000 ₸; известные платежи 89 000 ₸. Платёж третьего договора намеренно отсутствует.
3. Укажите доход 400 000: доля известных платежей будет 22,3% с отметкой частичного расчёта.
4. На странице проверки добавьте платёж третьего договора 15 000 и сохраните. Известные платежи станут 104 000 ₸, доля — 26%.
5. Загрузите собственный текстовый PDF и сверьте каждую строку с источником. Обезличенный образец нового макета поможет дополнить правила извлечения.

Автоматические проверки:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

`pypdf` нужен только тестам (создание зашифрованных и пустых PDF), поэтому он вынесен в `requirements-dev.txt`.

## Что поддерживается и что ограничено

- Локальное извлечение текста PDFium; подписи подробных блоков «Контракт», суммы с валютами, отдельные статусы и роли. Использованы публичные полные и краткие образцы ПКБ: <https://www.1cb.kz/assets/doc/pko-full.pdf> и <https://www.1cb.kz/assets/doc/pko-short.pdf>.
- Проверен предоставленный пользователем персональный макет ПКБ с договорами на нескольких страницах. Разбор объединяет продолжения до следующего контракта, сохраняет страницу каждого денежного поля и учитывает явную фазу договора. Заявки и их платежи в договоры не преобразуются; статус «Стандартные кредиты» сам по себе не означает действующий договор. Личные данные из отчёта в тестовые образцы не включены.
- В ПКБ извлекаются `credit_limit` с отдельной `credit_limit_currency`, `start_date`, `end_date` и `max_overdue_days_history`. Дата окончания — плановая дата из договора, а не дата фактического закрытия. Исторический максимум читается из явного поля максимального количества дней, отдельно от текущей просрочки; помесячная таблица не подменяет это поле. Неизвестные значения остаются `null`. Поля можно проверить и исправить в интерфейсе; `sources` сохраняет исходное значение и страницу после правки.
- `report.inquiries_30d` и `report.inquiries_90d` — число распознанных записей журнала запросов, включая повторные обращения в один день. Окна составляют 30/90 календарных дней относительно даты выдачи PDF, включая этот день; системная дата для счётчиков не используется. Будущие даты исключаются. `report.sources` содержит страницы, границы окон и дату отсчёта; `inquiry_events` хранит только дату, вид записи и страницу, без ФИО/ИИН/названия заявителя. В `inquiries_by_kind` отдельно считаются кредитные и персональные отчёты и мониторинг по доступному виду записи.
- Количество запросов не равно количеству заявок на кредит. Эти счётчики отражают распознанный журнал предоставленного PDF, а не доказанную полноту базы бюро. При отсутствии журнала, неизвестном макете, ошибочной дате записи или отсутствии даты выдачи счётчики не заменяются нулями; нулевое число возможно для явно пустого журнала или распознанных записей вне окна.
- Сводные таблицы, история просрочек и первоначальные лимиты не подменяют текущие поля договора. При несовпадении числа договоров со сводкой показывается предупреждение.
- Поддержана русскоязычная краткая форма ГКБ с таблицей из 13 колонок; проверена на предоставленном файле. Колонки читаются по геометрии таблицы через pdfplumber, итоги сверяются со строкой «Итого». Данные исходного отчёта в тестовые образцы не включены.
- В ГКБ сохраняются `next_payment` (предстоящий платёж) и `payment_frequency`. При неизвестной периодичности предстоящая сумма включается в `payment` с `payment_basis: "assumed_monthly"`. Такие суммы помечены в обзоре, списке и симуляторе и не считаются подтверждёнными (`payment_complete: false`, `payment_assumed_count`). Пользователь может отдельно подтвердить месячную периодичность или исправить сумму; исходный `next_payment` и источник сохраняются. Явная двухнедельная и разовая периодичность не подменяется месячной.
- В краткой форме ГКБ завершённые договоры учитываются только как число из сводки (`declared_closed`). Подробные строки и история просрочек завершённых договоров в этой форме отсутствуют; фиктивные договоры для заполнения списка не создаются.
- PDF внутри DER CMS SignedData с вложенным PDF читается локально. Поддерживается определённая длина DER и примитивное поле eContent; это извлечение содержимого, без проверки ЭЦП и сертификатов. Произвольные бинарные префиксы перед PDF не принимаются.
- Другие макеты ПКБ и ГКБ требуют отдельной проверки. Сканированные и защищённые паролем PDF не поддерживаются.
- Пустое значение остаётся `null`. Закрытые/отозванные договоры, гарантии и неуточнённые роли/статусы исключаются из сумм. Созаёмщику учитывается указанный в отчёте полный платёж, доля ответственности не определяется.
- В ПКБ периодические и минимальные платежи без явной месячной подписи получают `payment_basis: "assumed_monthly"`. До подтверждения периодичности пользователем они сохраняют пометку предположения в итогах, таблице и симуляторе. Явно месячные поля получают `reported_monthly`; источник и исходное значение сохраняются после подтверждения.
- Валюты считаются отдельно. Суммы с неизвестной валютой не складываются и не конвертируются. Доход в интерфейсе — тенге, вводится пользователем; банковский КДН не рассчитывается. Разница дохода и учтённых платежей не является оценкой свободного бюджета.
- Текущая просроченная сумма не прибавляется повторно к остатку. Сумма «Задолженность» является суммой извлечённых остатков, а не суммой полного досрочного погашения.
- Дата выдачи PDF и даты актуальности договоров могут различаться. Новая выдача в блоке заявок может ещё не иметь отдельной записи в действующих обязательствах; автоматически прибавлять её сумму и платёж нельзя из-за возможного пересечения с договорами.
- Исправления действуют в этой сессии. Выгрузка JSON содержит исходные ссылки и пометку редактирования; PDF бюро не изменяется.

## Симулятор полного закрытия

Вкладка «Что если» считает по сохранённым сведениям текущего разбора. В списке только действующие договоры заёмщика/созаёмщика выбранной валюты. Галочки предполагают полное закрытие выбранного обязательства, включая договор и лимит карты. Исходный статус договора не изменяется.

Показаны месячные платежи до/после, их известное снижение, известные остатки выбранных договоров и доли введённого дохода в тенге. При отсутствии платежей, остатков, полноты списка или подтверждённой периодичности выводы остаются частичными. Полное закрытие всех распознанных договоров не доказывает отсутствие неучтённых обязательств. Сумма остатков не заменяет банковскую сумму полного досрочного погашения на конкретную дату.

Выбор и расчёт выполняются локально без HTTP-запросов. Доход общий с обзором. После исправления данных сценарий пересчитывается, недействующие/удалённые записи исключаются из выбора. Новый отчёт или очистка сбрасывают сценарий. JSON содержит отдельный `simulation`; исходные договоры сохраняются. Денежные итоги сценария — десятичные строки с двумя знаками, сложенные через целые тиыны (`BigInt`), чтобы сохранить точность больших сумм.

Арифметические проверки симулятора: `node tests/test_scenario.cjs`.

## Данные и архитектура

- Никаких внешних AI/API-запросов, внешних шрифтов или аналитических трекеров.
- Загруженный файл передаётся локальному серверу, обрабатывается отдельным процессом с ограничением 35 секунд и не записывается на диск. Парсер ограничивает размер и количество страниц. Максимум два одновременных запроса.
- Сведения хранятся в памяти страницы; localStorage, cookies и серверная база не используются. Скачанный пользователем JSON хранится на его компьютере.
- Проверка Host, Origin и токена запросов препятствует обычным запросам с посторонних веб-страниц. Это не изоляция от других процессов или людей с доступом к компьютеру.
- PDF не проверяется на подлинность. Для запуска с реальными участниками нужны отдельные решения по идентификации, правам доступа, среде обработки, хранению, согласиям и эксплуатации.

`credit_report.py` — извлечение ПКБ и общая арифметика; `pkb_enrichment.py` — лимиты, сроки, исторический максимум и журнал запросов ПКБ; `gkb_report.py` — краткая форма ГКБ; `pdf_input.py` — чтение PDF из контейнера; `app.py` — локальный HTTP/API; `web/` — интерфейс; `tests/` — финансовые и загрузочные проверки.

Следующее увеличение: адаптация парсера под реальные обезличенные отчёты, затем отдельно подключение выбранной AI-модели для объяснений. Извлечение и расчёт остаются проверяемыми компонентами.
